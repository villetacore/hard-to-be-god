# Разработка и диагностика

Проверенная версия исходников: 0.3, 18.10.2026. Версия пакета Cargo пока 0.1.0 — это не отдельный выпуск игры.

## Как ориентироваться

| Изменение | Начать с | Затем проверить |
| --- | --- | --- |
| Новый житель | npc.rs: PEOPLE, BONDS, population | Уникальное имя, дом/работа, связи, target в AI |
| Новый предмет | items.rs: Item, ALL, name | nourishment, gift_value, color, инвентарь, схема AI, сохранения |
| Новое место | world.rs: places и геометрия | Доступность маршрута, source/public, тест every_place_is_reachable_from_the_market |
| Новое действие | ai.rs: Action, ACTIONS, SYSTEM_PROMPT | sanitize, npc::apply, gameplay::act/steer, завершение и отказ, тест |
| Новая сила | powers.rs: Power/cast/tick | Стоимость, очевидцы, epoch, управление и UI main.rs |
| Новое поле памяти | npc.rs: Npc/Request/SavedNpc | Значение для старых сохранений, ограничение длины, контекст AI |
| Новый параметр LM Studio | ai.rs: Config | ai_config.json, reload/cached_model, README, HTTP-тест |

Не добавляйте только описание действия в промпт: нужны выполнение, предусловия, завершение и проверка отказа.

## Проверка изменения

Из корня проекта:

~~~powershell
cargo test --offline
cargo clippy --offline -- -D warnings
cargo run --offline -- --smoke
cargo run --offline -- --smoke-actions
~~~

Визуальные прогоны открывают окно, сохраняют PNG в docs и закрываются. Они не проверяют качество LLM. --smoke-actions не заменяет ручную проверку клавиатуры, мыши и длительной игры.

Для реального сервера:

~~~powershell
cargo run --offline -- --check-ai
~~~

Ожидается LM Studio OK и разобранное решение Милы. Проверка не требует запуска графического окна. При ошибке — ненулевой код. check-ai.cmd выполняет ту же команду с паузой консоли.

## Разбор «нейросеть не работает»

1. Запускать через run-game.cmd: он собирает текущие исходники. Прямой старый exe может не соответствовать коду.
2. Проверить режим запуска. Аргумент --offline после разделителя -- отключает модель; cargo --offline до разделителя отключает только сетевую загрузку зависимостей.
3. В LM Studio включить Developer / Start Server и загрузить языковую модель.
4. Выполнить запросы:

~~~powershell
Invoke-RestMethod http://127.0.0.1:1234/api/v1/models
Invoke-RestMethod http://127.0.0.1:1234/v1/models
~~~

Для другого адреса использовать base_url из ai_config.json. В native-ответе нужен type=llm и непустой loaded_instances. Embedding-модель для диалога не подходит.

5. Выполнить --check-ai. Доступный список моделей не доказывает работоспособность генерации.
6. При работающем --check-ai проверить игровой статус, F6, ожидание реплики и текущий персонаж. Пока меняется model/base_url, надёжнее перезапустить игру: кэш хранится отдельно в каждом worker.
7. Ошибка JSON требует проверки structured_output и модели. finish_reason=length — лимита ответа/reasoning. Ошибка транспорта — доступности сервера либо таймаута; текущее сообщение не различает эти причины.

При включённой авторизации используйте LM_STUDIO_API_KEY в окружении запуска. Не помещайте токен в отчёт об ошибке.

## Что собрать для воспроизведения

- Команда запуска, версия исходников/дата, адрес без секретов.
- Имя и квантование модели, контекст, parallel в LM Studio и игре.
- Точная реплика, имя NPC, ситуация: движение, разговор, загрузка, чудо.
- Статус игры и вывод --check-ai.
- Ожидаемое действие, фактическое действие, приблизительная длительность.
- Копия сохранений до воспроизведения, если проблема зависит от мира.

## Договор ответа модели

Все девять полей обязательны в JSON Schema. Decision::parse допускает отсутствие некоторых строк для совместимости, но запрещает неизвестные поля и неизвестный Action.

| Поле | Назначение | Лимит схемы |
| --- | --- | --- |
| thought | Короткая игровая мысль | 150 символов |
| goal | Текущая цель | 80 |
| about_player | Мнение о путнике | 110 |
| speech | Публичная реплика | 220, непустая при обращении |
| action | Действие | 16 значений ACTIONS |
| target | Адресат | Пусто, путник, известное имя |
| item | Предмет | Пусто либо имя Item |
| place | Место | Пусто либо допустимое место, включая дом |
| trust_delta | Изменение доверия | -5…5 |

После разбора sanitize нормализует аргументы и заменяет часть невыполнимых решений на Idle. Затем gameplay::act разрешает ссылки, а steer выполняет действие. Ни схема, ни порядок полей не гарантируют, что текстовая мысль действительно объясняет выбор или обещание будет выполнено.

## Проверка одной игровой ситуации

1. Попросить Милу дать хлеб; проверить не только реплику, но и уменьшение её запаса и увеличение запаса адресата.
2. Повторить без хлеба, но с мукой; затем без муки. Убедиться в понятном отказе/новом плане.
3. Попросить обратиться к далёкому Гордею: слова должны прозвучать после прибытия.
4. Сохранить посреди поручения и загрузить. Текущее прерывание поручения — известное ограничение.
5. Запустить ответ, затем изменить ситуацию чудом или загрузкой: проверить старую эпоху. Это приоритетный риск, пока не гарантия корректности.
6. Остановить LM Studio: город должен жить по правилам, ошибка должна быть видна. Возобновить сервер и проверить F6.


## Подготовка репозитория — 1 ноября 2026

Тесты и Clippy запускаются в GitHub Actions на Ubuntu. Оконные smoke-проверки
остаются локальными. Не используйте старые результаты аудита как доказательство
прохождения тестов текущего коммита. Подробности изменений — в ../CHANGELOG.md.

Авторство владельца задаётся локально в `.git/config`, не в переносимых скриптах.
Перед коммитом проверяйте `git var GIT_AUTHOR_IDENT` и `git status --short`.
Локальные файлы остаются на диске, но исключены из публикации через `.gitignore`.
